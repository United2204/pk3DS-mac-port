pkpk3DS Mac Randomizador

HERRAMIENTAS DE PROYECTO

Flujo de proyecto

Extraé, validá, construí y empaquetá tu workspace siguiendo el mismo orden mental de pk3DS para Windows.

1

EXTRACCIÓN

Extraer un CXI, 3DS o CIA

Elegí un CXI, 3DS o CIA desencriptado y una carpeta nueva o vacía. Se generará un workspace con RomFS, ExeFS y exheader.bin.

⌁
El origen se conserva intacto.La carpeta de destino debe ser nueva o estar vacía.

2

VALIDACIÓN

Validar un workspace

Cargá la carpeta extraída para detectar el juego, el Title ID y las herramientas compatibles.

⌁

El origen se abrirá solo para lectura.

3

CONSTRUCCIÓN

Construir RomFS / ExeFS

Cargá un workspace para continuarEsta construcción no modifica el origen.

4

RECONSTRUCCIÓN

Crear una ROM .3ds

Usa el RomFS, ExeFS y exheader del workspace cargado para ensamblar una ROM nueva. La opción recortada evita el padding de tarjeta y ocupa menos espacio.

Se requiere un workspace completo.Debe incluir RomFS, ExeFS y exheader.bin.

5

CRO / CRR

Verificar y reconstruir hashes

Recalcula los hashes internos de todos los CRO y la tabla RomFS/.crr/static.crr. Se genera un parche LayeredFS con solo los archivos que cambian; el workspace original queda intacto.

Se requiere RomFS con CRO y static.crr.Esto corrige hashes internos y la tabla de verificación; no elimina la firma RSA de consola.

6

CIA

Crear un archivo .cia

Reconstruye primero una ROM .3ds en staging y luego la convierte a un CIA desencriptado con makerom, compatible con Azahar. La conversión omite las firmas retail del contenido modificado; la versión macOS arm64 se incluye en la aplicación.

Se requiere un workspace completo.makerom arm64 está incluido; CIA desencriptado y sin firmas retail del contenido reconstruido.

7

PARCHE

Crear parche de redirección

Porta el parche “Redirect [CIA]” de pk3DS: cambia las referencias de los GARCs seleccionados en code.bin y copia sus archivos al árbol a0/. Esto genera los contenidos del parche; todavía no firma ni construye un archivo CIA.

Se requiere ExeFS con un code.bin parcheable.Si está comprimido con BLZ, la aplicación lo normaliza en memoria; el origen se conserva intacto.

8

ARCHIVOS GARC / MINI

Desempaquetar o empaquetar

Trabaja sobre una copia de los archivos: el desempaquetado genera una carpeta nueva y el empaquetado nunca altera la carpeta de entrada.

Desempaquetado automático

Detecta y abre automáticamente GAR, GARC, Mini, ALYT, Shuffle ARC, DARC, SARC o FARC. Si el archivo no tiene una extensión reconocible, se inspecciona su firma interna. Si dejás vacía la salida, GARC/DARC/Mini usan las carpetas Windows _g, _d y _XX; los demás formatos usan una carpeta -unpacked.

Al detectar un Mini, también puede abrir los contenedores Mini que estén dentro de sus bloques. El límite de seguridad es de ocho niveles y la opción se puede desactivar para conservar una extracción raw plana.

⌁
La fuente queda intacta.Se deriva al desempaquetador específico del formato detectado.

Empaquetado automático

Usa las convenciones de Windows: una carpeta terminada en _g se empaqueta como GARC, _d como DARC y _XX como Mini (por ejemplo, encdata_zo).

⌁
No elimina la carpeta de entrada.El formato se determina por el sufijo del nombre.

GARC Shuffler

Reordena las referencias FATB de las entradas sin carpeta, como la herramienta de Windows. El bloque de datos no se mueve y se genera un GARC nuevo; el original nunca se modifica.

⌁
Se crea una copia nueva.Algunos archivos dependen de posiciones concretas: conservá siempre el original.

Archivos Mini / BinLinker

Desempaquetá o empaquetá contenedores de dos letras como WD, ZO o EP. Cada archivo de la carpeta representa un bloque y la entrada siempre queda intacta.

Genera una carpeta nueva con bloques numerados.

⌁
Empaqueta los archivos en orden alfabético.El modo automático también busca el original junto a la carpeta.

Desempaquetar ALYT (SARC envuelto)

ALYT es un contenedor que guarda etiquetas, símbolos y un SARC interno. Se extrae el árbol SARC conservando el archivo original.

⌁
Extrae y valida el SARC embebido.También informa cuántas etiquetas y símbolos tenía el contenedor.

Empaquetar ALYT (SARC envuelto)

Elegí una carpeta con los archivos del SARC interno. Las etiquetas y símbolos son opcionales y se guardan en slots UTF-8 fijos; una línea representa una entrada.

⌁
Genera un ALYT nuevo y valida el SARC interno.La carpeta original queda intacta y la salida no sobrescribe archivos.

Desempaquetar GAR legacy

GAR es un contenedor genérico distinto de GARC. Extrae sus archivos usando las dos tablas de nombres y valida todos los offsets antes de escribir.

⌁
Genera una carpeta nueva con los nombres originales.El origen se conserva intacto.

Desempaquetar Shuffle ARC

Extrae los fragmentos numerados del contenedor usado por algunas herramientas de Windows. Se conservan como bytes raw aunque no sean ZIP válidos.

⌁
Genera una carpeta nueva con fragmentos 0.zip, 1.zip…El origen se conserva intacto.
